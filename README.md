# Деплой бэкенда (Google Apps Script)

## 1. Привязать скрипт к таблице

1. Открой `Uzbek_Mentor_2.xlsx` (загруженную в Google Sheets — если она ещё как xlsx,
   сначала «Файл → Сохранить как Google Таблицы»)
2. Расширения → Apps Script
3. Удали содержимое `Code.gs` по умолчанию, вставь наш `Code.gs`
4. Создай второй файл `Setup.gs` (значок «+» рядом с Файлы), вставь его содержимое

## 2. Указать токен бота и ID таблицы

1. В редакторе Apps Script: значок шестерёнки (Настройки проекта) → Свойства скрипта
2. Добавить свойство: `BOT_TOKEN` = токен твоего Telegram-бота (из BotFather)
3. Добавить свойство: `SPREADSHEET_ID` = ID таблицы из её URL —
   `https://docs.google.com/spreadsheets/d/ЭТА_ЧАСТЬ/edit`, только сама эта часть,
   без `/edit` и остального

Это нужно, потому что `SpreadsheetApp.getActiveSpreadsheet()` не работает ни при
запуске функции не из привязанного контекста, ни (что важнее) при вызовах через
Web App — там вообще нет понятия «активной» таблицы, поэтому открываем её явно по ID.

## 3. Создать служебные листы

1. В выпадающем списке функций (сверху) выбери `setupSheets`
2. Нажми ▶ Run
3. Разреши доступ (Google спросит один раз) — появится алерт «Готово»

Это создаст листы `users`, `user_words`, `sessions`, `admins`, `reading_articles`,
`app_settings`. Лист `words` не трогается.

## 4. Добавить себя как админа (для будущей админ-панели)

В листе `admins` вручную добавь строку: свой Telegram `user_id`, имя, дата.
(Свой user_id можно узнать у бота @userinfobot)

## 5. Задеплоить как Web App

1. Deploy → New deployment
2. Тип: **Web app**
3. Execute as: **Me**
4. Who has access: **Anyone**
5. Deploy → скопировать URL (заканчивается на `/exec`)

## 6. Подключить фронт

В корне `uzbek-mentor-app`:
```bash
cp .env.example .env
```
Вставить скопированный URL в `VITE_API_URL`, пересобрать (`npm run build`).

## Важно

- При каждом обновлении кода `Code.gs` нужно делать **новый деплой** (Manage deployments →
  ✏️ → New version), просто сохранение файла URL не обновляет
- Бесплатные квоты Apps Script: ~20 000 вызовов/день на некоторые сервисы, до 6 минут
  на выполнение скрипта — для MVP и первых пользователей достаточно с запасом
